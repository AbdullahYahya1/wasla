# Wasla Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> Execution note: the author of the spec executes this plan inline (superpowers:executing-plans), because the
> engine work depends on wamove internals read during the real transfer. The code for each task lives in
> its commit; this plan fixes the files, interfaces and tests.

**Goal:** A free, open-source Mac app (pywebview + HTML) that walks anyone through moving WhatsApp from Android to an already-set-up iPhone, with live % and time left, in Arabic and English.

**Architecture:** One Python process. pywebview shows `ui/index.html`; the UI calls `window.pywebview.api` (class `Api` in `bridge.py`), which runs one job at a time on a worker thread and pushes `Event`s back with `evaluate_js`. Engine modules wrap wamove (pinned commit) and add progress, a parallel thumbnail cache, key-order detection and friendly errors.

**Tech Stack:** Python 3.13, uv, wamove @ 989b268, pymobiledevice3, pywebview ≥ 5, pytest, PyInstaller; plain HTML/CSS/JS.

## Global Constraints

- License GPL-3.0-or-later; README and About credit wamove (alicin/wamove).
- Never write the 64-digit key or a backup password to disk or logs.
- Every user-visible string exists in `strings/en.json` and `strings/ar.json`; Arabic is RTL.
- Not affiliated with WhatsApp/Meta: say so on Welcome, About and the site; no WhatsApp logo.
- No network access except downloading platform-tools from `https://dl.google.com/android/repository/`.
- Only `wamove restore`'s domain is restored (`AppDomainGroup-group.net.whatsapp.WhatsApp.shared`), with
  `remove=False`, exactly as wamove does.
- Work folder: `~/Library/Application Support/Wasla/work` (mode 700).

### Task 1: Project skeleton, events, progress, state

**Files:** `pyproject.toml`, `LICENSE`, `src/wasla/__init__.py`, `src/wasla/events.py`, `src/wasla/progress.py`, `src/wasla/state.py`, `tests/test_progress.py`, `tests/test_state.py`, `tests/test_events.py`

**Interfaces (produces):**
- `events.Event(step: str, kind: Literal["progress","log","done","error","need"], pct: float|None=None, eta_s: float|None=None, phase: str|None=None, data: dict={})` with `.to_json() -> str`
- `events.Emitter(sink: Callable[[Event], None], min_interval: float = 0.12)`: `.emit(event)`; drops progress events closer than `min_interval` for the same step+phase except pct ≥ 100; never drops non-progress events.
- `progress.Rate(total: float)`: `.update(done: float, now: float|None=None) -> tuple[pct, eta_s|None]` (EMA of rate, ETA None until 3 samples / 2 s).
- `state.State(path: Path)`: `.load()`, `.save()`, `.done(step) -> bool`, `.mark(step, **stats)`, `.get(step) -> dict`, `.reset_from(step)`; JSON, atomic write.

- [ ] Tests: Rate gives 50% at half, ETA ≈ remaining/rate for steady rate, None at start; Emitter throttles and always passes done/error; State round-trips, reset_from clears later steps, atomic write leaves no `.tmp`.
- [ ] Implement; `uv run pytest -q` passes; commit.

### Task 2: Key handling (`engine/keygrid.py`)

**Interfaces:** `normalize(text) -> str` (strip spaces, dashes, colons, newlines; lowercase), `candidates(text) -> list[tuple[str, str]]` returning `("as_typed", key)` and `("rows_rtl", key)` (each row of 4 groups reversed, when the input is 16 groups) without duplicates; `find_working_key(text, sample: Path) -> tuple[str, bytes]` raising `KeyError_` codes `key_format` / `key_wrong`.
- [ ] Tests build a real crypt15 sample with wamove's format (encrypt with AES-GCM using `crypt15.derive_aes_key`, header from a fixture file made by `tests/make_crypt15.py`), then: typed order works; RTL grid works when typed LTR; wrong key → `key_wrong`; 63 digits → `key_format`.
- [ ] Implement; tests pass; commit.
